## O problema (confirmado no código)

`render_panel` emitia **uma** página com **cinco** seções e a nav apontava para **âncoras** dela
(`#inicio-section`, `#producao-section`, `#trending-section`, `#videos-section`) mais
`#precisa-section` e `#new-video-section`. Navegar só rolava a tela — todo o HTML vinha junto.

## Decisão implementada

Rotas de servidor reais (não roteador de hash), uma tela por rota:

| Tela | Rota | Conteúdo |
| --- | --- | --- |
| Início | `GET /studio/panel` | hero + criar vídeo (`#new-video-section`), `#inicio-producao-section` (resumo de Produção), `#precisa-section` ("Precisa de você"), `#inicio-tendencias-section` (resumo de Tendências), `#videos` |
| Produção | `GET /studio/panel/producao` | `#producao-section` completo (funil `grid-summary` + status por fase + nota de custo) |
| Tendências | `GET /studio/panel/tendencias` | `#trending-section` completo (lista, filtros por região/pilar, evidências, «Criar Vídeo deste Tema», modal de pilares) |
| Vídeos | `GET /studio/panel/videos` | **302** → `/studio/panel#videos` (destino real, sem link morto) |

A casca é única (`_render_panel_page(view, mode=…)`): sidebar, topbar, rail e o mesmo script
guardado por presença de elemento. O que muda por `mode` é **só o que entra em `<main>`**. Assim não
há duas cópias do shell e, ao mesmo tempo, o HTML de uma tela nunca aparece dentro da outra.

Sem `role="tablist"` para a navegação de páginas (a nav continua `nav` + `aria-current="page"` no
item ativo; a aba de origem do hero segue legítima, é um widget dentro da tela).

## O que mudou por tela

- **Início** deixou de emitir `#producao-section`/`#trending-section`/`#videos-section`. Ganhou:
  - `#inicio-producao-section` — legenda dos três estados **com contadores** + resumo. Estado vazio:
    a mesma mensagem honesta de antes ("Nenhuma execução registrada") com os 8 passos e "Não há
    percentual"; com execução: contadores + link **Ver Produção**.
  - `#inicio-tendencias-section` — resumo (nº de temas no período + última coleta) + link **Ver todas
    as tendências**. Nada de cartões/evidências/filtros (isso é da tela Tendências).
  - `#videos` (antes `#videos-section`) — o bloco de vídeos continua no Início.
- **Produção** isolada: `grid-summary` + "Status por fase" + nota de custo + rail (Custo do mês /
  Estado das fases). `<h1>Produção</h1>` (exatamente um).
- **Tendências** isolada: `trends-card` completo + `#categories-modal` (só aqui) + rail "Frescor".
  `<h1>Tendências</h1>` (exatamente um).
- **`#precisa-section`** (atenção humana) permanece **no Início**, como decidido.

## UI/acessibilidade (modern-web-guidance)

Consultei a skill antes de escrever HTML/CSS/JS (`navbar`, `tabs`, `accessibility`). Aplicado:

- A nav continua um `<nav>` com links reais (`<a>`), sem `role="menubar"/"menu"/"menuitem"` nem
  tratamento de setas — é navegação, não menu de aplicação.
- `aria-current="page"` no item ativo, definido no servidor, e o CSS já usa `[aria-current]` como
  gancho visual; o indicador não é só cor (`box-shadow: inset 3px 0 0` desenha uma barra — WCAG 1.4.1).
- **Nada de `tablist` para navegação de páginas** (a guidance proíbe explicitamente).
- «Criar Vídeo deste Tema» virou `<a href>` (navega para outra página) em vez de `<button>`: link
  navega, botão age.
- `nonce`/CSP, `Cache-Control: no-store` e `aria-live="polite"` no painel seguem intactos.

### Modern Web Guidance

- **`tabs`**: a navegação entre Início/Produção/Tendências usa links com `aria-current="page"`, não o
  padrão ARIA de abas — a guidance é explícita: "DO NOT use this or the WAI-ARIA tabs pattern for page
  navigation, even if it is intended to be presented as a tabbed interface."
- **`navbar`**: mantive `aria-current="page"` definido no servidor como gancho da página atual, sem
  `role="menubar"`/`role="menu"` (a guidance separa navegação de menu de aplicação), e o indicador
  visual já não depende só de cor ("Do not indicate the current page with color alone (WCAG 1.4.1)").

## Limitações reais / o que **não** consegui

- **Custo de leitura no banco não foi reduzido.** As três rotas reusam o mesmo caso de uso
  `uc.panel.execute(days, project_id)`, que monta a projeção inteira (vídeos, totais, mês, tendências,
  categorias). Não criei projeções por tela porque cada uma ainda depende da mesma base (Início usa
  vídeos+totais+mês+contagem de tendências; Produção usa vídeos+totais+mês; Tendências usa
  tendências+categorias+contagem por tema). O ganho entregue é o de **HTML** (uma tela por rota) — que
  é o critério de aceite — e não o de consulta. Reduzir a leitura exigiria um caso de uso/projeção
  por tela (fora do esforço permitido nesta fatia).
- `base_href` ficou **sem uso** em `build_sidebar_nav`/`render_sidebar`, mantido por compatibilidade
  porque as telas de Estilos/Conexões/Canais o passam e estão fora do escopo desta fatia (não podia
  tocar nelas). Um passe futuro pode removê-lo junto com esses call sites.
- A **primeira** definição de `create_form_html` (o `<details>` em `panel.py`, hoje morta porque é
  reatribuída antes do uso) continua no arquivo: é código morto **pré-existente**, não removido para
  não ampliar o escopo.
- Não rodei a suíte inteira (VM apertada), conforme instruído. Sem push/merge remoto; árvore limpa.
