## Objetivo

O **canal do estúdio** (`ChannelProfile`) passa a **referenciar** qual **canal do YouTube**
ele publica (`youtube_channel_id`), e o domínio ganha um **resolvedor puro** que diz qual
**autorização** (`ChannelAuthorization`) valida esse canal. Esta fatia entrega a **referência**
e a **resolução** — **não** religa o `RunPublication` (isso é a YT-03): o caminho de publicação
segue intacto.

## O que foi feito

### Migração (`0037_channel_youtube_target.sql`) — aditiva

```sql
ALTER TABLE studio.channel_profiles
    ADD COLUMN youtube_channel_id text REFERENCES studio.youtube_channels(youtube_channel_id) ON DELETE SET NULL;
CREATE INDEX channel_profiles_youtube_channel_idx
    ON studio.channel_profiles (youtube_channel_id) WHERE youtube_channel_id IS NOT NULL;
```

Mesmas escolhas da referência ao estilo (0034): coluna anulável, sem backfill; FK para a
**identidade oficial** do canal (`studio.youtube_channels`, `UC...`), não para a conta nem para a
autorização; `ON DELETE SET NULL` para limpar a identidade do YouTube **destacar** o canal em vez
de bloquear ou apagar; índice parcial porque só importa o caminho raro "quem aponta para este canal".

### Domínio (`domain/channel.py`)

- `ChannelProfile.youtube_channel_id: str | None = None`, validado por `validate_youtube_channel_id`
  (formato do id do YouTube, `[A-Za-z0-9._-]{1,128}`) — **não** pelo `check_id` hex32 dos ids internos.
  Tipo não-string e string fora do formato são recusados (`ChannelFieldInvalid` /
  `YouTubeChannelIdentityInvalid`). Campo adicionado a `CREATABLE_FIELDS` e `UPDATABLE_FIELDS`.
- Erro nomeado `ChannelYouTubeTargetNotFound(ChannelError, LookupError)`, ao lado de
  `ChannelStyleNotFound`: aponta para um canal do YouTube que não existe.
- **Resolvedor puro**:

  ```python
  def resolve_publication_authorization(
      channel: ChannelProfile,
      authorizations: Iterable[ChannelAuthorization],
  ) -> ChannelAuthorization | None
  ```

  Devolve a primeira autorização **vigente** (`OAuthStatus.CONNECTED`) cujo `youtube_channel_id`
  casa com o destino do canal; `None` se o canal não escolheu destino, se não há autorização para
  ele ou se todas estão revogadas/expiradas. Também ignora autorizações de **outros** canais (não
  presume vínculo). Puro, sem I/O. **Não** foi acoplado ao `RunPublication`.

### Repositório (`channel_repo.py`)

- `_COLS`/`_insert`/`update` incluem `youtube_channel_id`; o snapshot por versão já o captura
  automaticamente (o `_snapshot` percorre os campos do dataclass).
- FK violada vira erro nomeado lendo `exc.diag.constraint_name`, agora distinguindo **qual** vínculo
  quebrou — antes a mensagem só sabia de projeto/estilo:
  - `youtube_channel_id` → `ChannelYouTubeTargetNotFound`;
  - `style_id` → `ChannelStyleNotFound` (VS-02, inalterado);
  - senão → `ChannelProjectNotFound`.

### API (`routes.py`)

- `ChannelProfileIn`/`ChannelProfileOut`/`_channel_out` ganham `youtube_channel_id` (round-trip).
- `ChannelYouTubeTargetNotFound` **e** `YouTubeChannelIdentityInvalid` (formato do id) mapeados para
  **422**; inexistência de projeto segue **404**.

## Limitações e observações honestas

- **Não religuei a publicação** (intencional): `RunPublication`, `tokens` e o caminho antigo por
  projeto continuam como estavam. Quem publica ainda usa o modelo antigo até a YT-03.

  uma autorização vigente para o mesmo canal, a escolha é determinística pela ordem de entrada; a
  política de "qual grant preferir" (ex.: mais recentemente validada) fica para quem ligar a YT-03.
