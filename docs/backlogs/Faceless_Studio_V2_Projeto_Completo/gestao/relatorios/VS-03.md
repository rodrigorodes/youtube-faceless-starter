# VS-03 — O estilo aplica no Render Plan

- **Branch:** `feat/vs03-style-apply`
- **Base:** `08aef55a85698e6c2279375f86751f10d371b688` (`08aef55`)
- **Escopo:** fazer o estilo visual do canal **efetivamente aplicar** no Render Plan —
  o plano deixa de gravar só a referência (`StyleSnapshot`) e passa a honrar `motion` e
  `music` do estilo. `transition` é **carregada** mas **não aplicada** (fatia futura).

## O que mudou (verbatim, por arquivo)

### `renderer/app/studio/domain/visual_style.py`
- Novo tipo puro `ResolvedStyle(snapshot: StyleSnapshot, motion: tuple[Motion, ...] = (),
  music: dict[str, int] = {}, transition: dict[str, Any] = {})` — a ponte entre o
  agregado `VisualStyle` e o render: carrega a referência versionada **e** o que o render
  consome hoje (`motion`/`music`). `transition` fica carregada por fidelidade, sem fingir
  suporte (ver "Fora desta fatia").
- Nova função pura `resolve_style(profile, style, override=None) -> ResolvedStyle | None`:
  - `style` e `override` ausentes → `None` (renderer cai no bundle neutro).
  - `override` (o "pode sobrepor" do vídeo, VS-05) vence o do canal; o parâmetro já fica
    pronto mesmo que a chamada ainda não passe override.
  - `snapshot = StyleSnapshot(source="channel", style_id=estilo_efeito.id, version=estilo_efeito.version)`.
  - `motion`/`music`/`transition` vêm de `style.params` (ausente = vazio/default).
- Importa `StyleSnapshot` de `.render_plan` e `ChannelProfile` de `.channel` (domínio→domínio).

### `renderer/app/studio/application/ports.py`
- `RenderSpec.style` passa de `StyleSnapshot | None` para `ResolvedStyle | None` (mesmo
  nome de campo). Import trocado para `..domain.visual_style.ResolvedStyle`.

### `renderer/app/studio/application/render.py`
- `RunRender(... style_for: Callable[[str], ResolvedStyle | None] | None = None)`;
  a montagem `spec = RenderSpec(..., style=self.style_for(video.project_id) ...)` não muda
  (só o tipo do que o resolvedor devolve).

### `renderer/app/studio/domain/render_plan_builder.py`
- `build_render_plan` ganha `music_params: Mapping[str, Any] | None = None`.
- A trilha usa `params={} if not music else dict(music_params or DEFAULT_MUSIC_PARAMS)`:
  com params do estilo, aplica-os; sem estilo, mantém o default (**bpm 122, seed 7**).

### `renderer/app/studio/adapters/render_plan_ffmpeg.py`
- `_build_plan`:
  - `style_snapshot = (spec.style.snapshot if spec.style else None) or
    StyleSnapshot(style_id=DEFAULT_STYLE_ID, version=DEFAULT_STYLE_VERSION)`.
  - o ciclo de movimento: `spec.style.motion` (se não vazio) sobrepõe `self.cycle`; senão
    mantém `self.cycle` (Ken Burns por posição).
  - `music_params = spec.style.music if spec.style is not None else None`.
- `_motions(scene_ids, cycle=None)` passa a aceitar o ciclo efetivo; `None` = `self.cycle`.
  A sobreposição por `scene_id` (`self.motions`) continua vencendo.

### `renderer/app/studio/composition.py`
- `_style_for_project(project_id, channels, styles)` resolve de verdade:
  canal do projeto → `profile.style_id` → `PostgresVisualStyleRepository.get(style_id)` →
  `resolve_style(profile, style)`. Sem canal, sem `style_id` ou estilo inexistente → `None`;
  tolerante a `InvalidId` (como o `channel_guard_limits`).
- Novo `style_repo = PostgresVisualStyleRepository(connect)`; `style_for` fiado com
  `(channel_repo, style_repo)`. Import de `style_snapshot_for_channel` sai da composição
  (a função continua existindo e testada em `tests/test_render_plan_builder.py`).

## Fora desta fatia

- **Transição (`transition`): carregada, NÃO aplicada.** Confirmado por
  `grep -rn 'Transition(' renderer/app/studio/` — não há uso no builder/compilador/executor
  (só `StageTransition`/`RunTransition` de produção, sem relação). O contrato do plano
  representa `Shot.transition`, mas ninguém o preenche. Entra numa fatia futura; aqui o
  parâmetro viaja no `ResolvedStyle` sem suporte inventado.
- `caption`/`palette`/`voice`: VS-04.
- UX de Estilos + seletor no canal + **override do vídeo**: VS-05 (o `override` de
  `resolve_style` já está pronto, mas nada o alimenta ainda — falta `videos.style_id`).
