# F03 — Configuração efetiva de produção

**Status:** em execução (T01/T02 integradas; T03 em integração; T04 em stream) · **Dono/revisor:** a designar · **Dependências:** F00 ADRs; F01 para operações reais; F02.T02 para fluxo UI

**Gaps:** G06 G08 (pré-requisito de G07)

## Objetivo

Resolver e congelar entradas criativas antes do primeiro efeito, mantendo segurança operacional dinâmica.

## Tarefas

### F03.T01 — Contrato e resolução

- **Escopo:** Definir configuração tipada, schema versionado, proveniência e precedência; distinguir seleção de estilo inteiro de patch; defaults explícitos.
- **Arquivos/áreas candidatas:** `domain/production_run.py, domain/visual_style.py, application/config.py, composition.py` (confirmar no HEAD).
- **Dependências:** F00 ADRs; F01 para operações reais; F02.T02 para fluxo UI; tarefas anteriores desta fase quando alteram o mesmo contrato.
- **Aceite:** Mesmas entradas → mesma configuração canônica; ausência de perfil mantém legado; sem segredos.
- **Testes:** test_production_run.py, test_visual_style_domain.py, test_project_config_validation.py.
- **Risco:** Inconsistência histórica, concorrência, schema incompatível ou resolução divergente.
- **Rollback:** Migração aditiva; preservar snapshots e revisões; impedir início de runs incompatíveis até correção.
- **Evidência/status:** **concluída e integrada** (sem commit). `domain/effective_config.py`
  (novo, puro): `schema_version=1`, documento canônico determinístico (`canonical_json`,
  `content_hash` sha256, round-trip), precedência de estilo inteiro e de patches por chave,
  proveniência por campo/grupo com cobertura obrigatória, defaults legados explícitos quando não
  há perfil, recusa de token/chave/saldo/autorização. Testes: **66 passed** (20 novos).
  Limites: patches de vídeo/canal entram em F03.T02; `provider_policy` congela só profile+version.

### F03.T02 — Persistência e start

- **Escopo:** Persistir snapshot/referências imutáveis antes de efeitos; ligação atômica ao run; tratar conflito de versão e runs legados.
- **Arquivos/áreas candidatas:** `application/production.py, adapters/postgres/production_repo.py (confirmar símbolo), migrações` (confirmar no HEAD).
- **Dependências:** F00 ADRs; F01 para operações reais; F02.T02 para fluxo UI; tarefas anteriores desta fase quando alteram o mesmo contrato.
- **Aceite:** Não existe run novo com efeito sem config resolvida; concorrência e retomada mantêm referência.
- **Testes:** test_production_repo.py, test_production_coordinator.py, test_production_flow_db.py.
- **Risco:** Inconsistência histórica, concorrência, schema incompatível ou resolução divergente.
- **Rollback:** Migração aditiva; preservar snapshots e revisões; impedir início de runs incompatíveis até correção.
- **Evidência/status:** **concluída e integrada** (sem commit). `domain/run_config.py` (novo) define
  `RunConfigStatus`/`StoredRunConfig`/`RunConfigConflict`/`RunConfigIntegrityError`; a porta
  `ProductionRunConfigStore` é só de leitura e a escrita acontece em
  `create_run(..., config=snapshot)`, **na mesma transação** do run, etapas e outbox. Replay pela
  chave devolve o run existente com a config que ele tinha; hash divergente → `RunConfigConflict`
  (409), sem sobrescrever. Sem resolvedor, o run nasce `legacy` explícito (colunas nulas) e nunca
  é re-resolvido. Migração `0039_production_run_config.sql` (aditiva, CHECKs de status/schema e
  tudo-ou-nada); `docs/schema/studio.sql` e `docs/22-modelo-de-dados.md` regenerados. Testes:
  **116 passed** (17 novos) + **175 passed** no grupo integrado (produção/composição/db).
