# P05 — Aprovação e publicação: plano

**Goal:** `AWAITING_APPROVAL → APPROVED → PUBLISHED` com decisão humana auditada, publicação idempotente e retomável, miniatura e agendamento.
**Pronto quando (spec):** aprovar duas vezes publica uma só; matar o n8n no meio do upload e reiniciar retoma sem duplicar; ID em `publications`.

## Decisões
- Grafo de estados **não muda**. Vídeo `RENDERED` com QA reprovado só é aprovado com `override_reason`: o repositório faz `RENDERED→AWAITING_APPROVAL→APPROVED` na mesma transação (cada passo validado por `assert_transition`).
- `approve`/`reject` idempotentes (repetir devolve o estado, sem nova linha); decisão gravada em `studio.approvals` (única por vídeo) na mesma transação do estado. Título/descrição/tags do YouTube são definidos na aprovação (padrão: tema + roteiro); a descrição final (créditos de imagem, fontes, aviso de IA) é composta no `claim`.
- Publicação = fila no Postgres: `POST /publications/claim` pega atomicamente (`FOR UPDATE SKIP LOCKED`) um vídeo `APPROVED` sem publicação ou com lease vencido; lease de 30 min, `attempts`, teto de 5 tentativas. O n8n só executa (chamadas ao YouTube com a credencial dele) e reporta.
- `upload_uri` persistido (validado: https, `www.googleapis.com`, `/upload/youtube/v3/videos`, porque o n8n envia o token OAuth a essa URL). Retomada: consultar a sessão (`PUT Content-Range: bytes */N`); 200/201 = já concluído (o ID vem na resposta); 308 = baixar só o restante do MP4 com `Range` e continuar; 404/410 = sessão expirou, nova sessão.
- `mark_uploaded` grava ID + `PUBLISHED` atomicamente; repetir com o mesmo ID é no-op, ID diferente é 409. 4xx do YouTube não repete (`FAILED` até `retry` manual); 5xx/timeout só libera o lease.
- Miniatura: JPEG 1280×720 gerado da 1ª cena; falha não derruba a publicação (`thumbnail_set=false`).
- Página de prévia em HTML estático seguro (escape, CSP com nonce, sem dependências).
